# Molecular 3D Viewer Skill

## Purpose

Use this skill for 3D molecular visualization.

The 3D viewer is an interpretation aid, not the primary validation or connectivity layer.

## Phase Rule

Do not implement advanced 3D workflows before direct 2D construction, connectivity policy, and RDKit validation are stable.

## Separate 3D Categories

Do not merge these categories:

1. `vsepr-ideal-model`: idealized local electron-domain/molecular shape.
2. `generated-conformer`: coordinates generated by a named method/tool.
3. `curated-reference`: embedded or source-backed reference coordinates.
4. `external-database`: coordinates retrieved from a named database.
5. `user-imported`: coordinates supplied by the user.

## Recommended Input Type

```ts
export type Molecule3DInput = {
  format: 'sdf' | 'mol' | 'pdb' | 'xyz';
  data: string;
  label: string;
  sourceType:
    | 'vsepr-ideal-model'
    | 'generated-conformer'
    | 'curated-reference'
    | 'external-database'
    | 'user-imported';
  coordinateSource: string;
  sourceNote?: string;
  structureMatchStatus?: 'verified' | 'probable' | 'unverified';
};
```

A VSEPR ideal viewer may use a separate domain-specific input rather than pretending it is an experimental Molfile.

## Required Handoff

```text
connectivity policy passes
→ RDKit validation passes
→ exact validated structure identity is retained
→ coordinates/model obtained
→ structure match checked
→ viewer rendered with provenance
```

Do not use 3D coordinates to override failed 2D connectivity or validation.

## Angle Labels

Every displayed angle must identify its evidence type:

- VSEPR 이상각
- 생성 좌표 측정값
- 출처가 있는 참고값

Do not silently substitute one for another.

## Do Not

- Do not imply generated conformers are experimentally measured.
- Do not call the 2D editor layout a 3D model.
- Do not present a local VSEPR ideal model as the exact full-molecule conformation.
- Do not make 3D loading block 2D editing.
- Do not retain stale 3D data after the 2D structure changes.

## Test Cases

- viewer initializes on valid example
- previous structure clears before new load
- missing coordinates show friendly message
- coordinate source and match status are visible
- 2D edit invalidates stale 3D display
- VSEPR ideal and coordinate-based viewers are distinguishable
- measurement label identifies evidence type
- mobile-width rendering does not crash

## Output Standard

Report:

- input format
- model/source category
- coordinate source
- structure identity/match check
- rendering mode
- measurement evidence type
- fallback and invalidation behavior
- classroom warning
