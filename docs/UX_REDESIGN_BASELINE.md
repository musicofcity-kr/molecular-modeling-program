# UX Redesign Baseline

- 기준일: 2026-07-27
- 대상 앱: `apps/workbench`
- 기준 문서: `CODEX 분자구조모델링 메타프롬프트.md`
- 기준 커밋: `905b622e74727a70b8f4804bab456d55cd682775`
- 대상 배포: `https://molecular-modeling-program.vercel.app`
- 초기 QA 점수: **56/100**
- 완료 판정: **불가**
- 강제 상한: **CAP-B 활성**, CAP-A 완료 조건 미충족
- 스냅샷 성격: UX 개선 working tree를 적용하기 전 비교 기준

## 1. 목적과 판정 원칙

이 문서는 UX·UI 개선 전 상태를 고정하는 베이스라인이다. 코드, 기존 문서의
완료 주장, 과거 스크린샷을 그대로 신뢰하지 않고 2026-07-27에 확인한 기준
커밋의 코드, 같은 날 생성한 baseline PNG, 메인 에이전트가 실행한 명령 결과를
구분하여 기록한다.

이후 생성된 미커밋 UX 개선 diff는 이 문서의 초기 점수나 결함 상태를 소급해
바꾸지 않는다. 해당 변경은 `docs/UX_REDESIGN_IMPLEMENTATION.md`와
`docs/UX_REDESIGN_CHANGELOG.md`에서 별도로 추적하고, 최종 명령과 final
스크린샷이 준비된 뒤 QA 문서에서 재평가한다.

증거 수준은 다음과 같이 적용한다.

- **E3**: 2026-07-27 실제 명령 실행, 자동화 테스트 또는 실제 HTTP 응답으로 확인
- **E2**: 현재 코드와 단위 테스트로 확인
- **E1**: 정적 CSS, 기존 문서 또는 과거 증거로 추정
- **E0**: 현재 실행 증거 없음

정확한 시각이 제공되지 않은 실행 결과는 날짜만 기록한다. 과거
`CODEX_FEEDBACK.md`의 통과 기록과 `docs/qa/phase7/` 스크린샷은 이 베이스라인의
E3 증거로 승격하지 않는다. `docs/qa-screenshots/baseline/`의 PNG는 캡처된
화면의 시각 상태에 대해서만 E3이며, 캡처에 드러나지 않은 키보드·터치·오류
복구 동작까지 증명하지 않는다.

## 2. 요약

현재 앱은 설치, 타입 검사, 253개 단위 테스트, 빌드, 3개 Playwright 시나리오가
통과하고 프로덕션 URL이 HTTP 200을 반환한다. Ketcher 입력, RDKit 검증, 3D/VSEPR
표시, 학생 생각 작성·제출, 교사 피드백 반환의 정상 경로는 유지되고 있다.

그러나 새 메타프롬프트의 P0 요구사항과 현재 학생 화면 사이에는 큰 차이가 있다.

- 학생 화면은 5단계 진행 UI가 아니라 모든 핵심 영역을 한 페이지에 함께 표시한다.
- Ketcher 간편 편집 모드와 고급 편집 모드 전환이 없다.
- 모바일 하단 5탭, 안전 영역, 3D 터치 충돌 방지 규칙이 없다.
- 4개 지정 뷰포트의 baseline PNG는 생성되었으나, 390×844 캡처는 단순 세로
  적층과 8,185px 전체 페이지 높이를 보여 준다.
- 필수 오류 시나리오와 CH4·NH3·H2O 비교 흐름이 E2E에 없다.
- 현재 성공 E2E는 데스크톱 Chromium과 성공 응답 mock에 한정된다.

따라서 baseline 화면 증거와 자동화 E2E 자체는 존재하지만, 새 핵심 학생
흐름과 390×844 상호작용 전체가 E3가 아니므로 **CAP-B가 활성**이다.

| 프로덕션 URL HTTP 확인 | HTTP 200 | E3 | 2026-07-27, 정확한 시각 미기록 | 접속 가능성만 확인. 학생·교사 실제 사용자 흐름 성공을 의미하지 않음 |

### 경고 해석

- `npm ci` 성공은 의존성 설치 가능성을 증명하지만 peer/engine 경고와 12개
  vulnerabilities가 해소되었다는 뜻은 아니다.
- 빌드 성공은 배포 산출물 생성 가능성을 증명하지만 3Dmol eval 경고와 대형
  Ketcher/RDKit/3Dmol chunk의 성능 영향을 해소하지 않는다.
- HTTP 200은 프로덕션 첫 응답의 가용성 증거일 뿐 Firebase 입장, 제출, 교사
  인증 또는 화학 분석의 실물 E2E 증거가 아니다.

## 4. 현재 학생 흐름

현재 코드 기준 학생 흐름은 다음과 같다.

1. 생성형 AI 윤리 가이드를 확인한다.
2. 학생 역할을 선택한다.
3. 수업코드, 입장 확인코드, 수업용 닉네임을 입력한다.
4. 학생 작업 화면에서 분자 선택, 구조 편집, 검증 결과, 3D/VSEPR, 생각 작성과
   제출 영역을 한 페이지에서 함께 사용한다.
5. 구조 검증, 생각 작성, 서버 수업방 입장 상태를 만족하면 교사에게 제출한다.

주요 근거:

- `apps/workbench/src/components/student/StudentActivityShell.tsx`
  - `ActivityPicker`, `MoleculeDrawingStep`, `ValidationResultCards`,
    `ShapeViewerSection`을 한 번에 렌더링한다.
  - 학생 비교 슬롯은 현재 `null`이다.
- `apps/workbench/src/components/student/StudentActivityShell.test.tsx`
  - 단계형 위저드 없이 핵심 도구를 함께 표시하는 현재 계약을 테스트한다.
- `apps/workbench/src/app/App.test.tsx`
  - 학생 화면에 기존 위저드와 진행 레일이 없음을 확인한다.

이 직접 작업형 화면은 이전 제품 결정에는 부합하지만, 새 메타프롬프트의
`분자 선택 → 구조 만들기 → 구조 분석 → 3D 비교 → 생각 정리·제출` 5단계
시각 흐름과는 일치하지 않는다.

## 5. P0 요구사항별 베이스라인

### 5.1 시각적 5단계 흐름

- 현재 상태: 미구현
- 증거: E2
- 확인 사항:
  - 현재 단계, 완료 단계, 검토 필요, 오류 단계 상태를 계산하는 활성 컴포넌트가 없다.
  - 학생 단위 테스트가 단계형 위저드 부재를 명시적으로 보장한다.
  - 과거 위저드 CSS 일부는 남아 있으나 현재 렌더링 계약의 증거가 아니다.
- 영향: 시작점과 다음 행동이 한 페이지의 긴 스크롤 속에서 약해지며 CAP-B의
  핵심 원인이 된다.

### 5.2 학생용 간편 편집 모드

- 현재 상태: 미구현
- 증거: E2
- 확인 사항:
  - `KetcherEditor.tsx`는 Ketcher `Editor`를 직접 렌더링하고
    `disableMacromoleculesEditor`만 지정한다.
  - 간편/고급 모드 상태, 제한된 초심자 툴바, 전환 후 구조 보존 테스트가 없다.
  - 학생 외부 행동은 예시 선택, 예시 불러오기, `내 구조 확인하기` 중심이다.
- 영향: 초심자에게 전체 Ketcher 기능이 노출되고 메타프롬프트의 필수 도구
  위계와 일치하지 않는다.

### 5.3 VSEPR 근거표

- 현재 상태: 부분 구현
- 증거: E2
- 확인 사항:
  - 전자쌍 배열, 분자 구조, 결합 원자 수, 비공유 전자쌍 수, 입체수,
    예상 결합각, 확인 수준을 표시한다.
  - 전자쌍 배열과 분자 구조는 서로 다른 필드로 표시한다.
  - 중심 원자가 근거표의 고정 필드가 아니며, `결합 원자 수`가
    `결합 전자 영역 수`를 교육적으로 정확하게 표현하지 못한다.
  - 극성 판단 단서는 기본 근거표에 없다.

### 5.4 참고 3D와 VSEPR 예상 모형

- 현재 상태: 성격 구분은 구현, 학생 비교 흐름은 부분 구현
- 증거: E2
- 확인 사항:
  - 두 뷰어에 참고 자료와 교육용 예측 모형의 차이 및 한계 문구가 있다.
  - VSEPR 뷰어는 비공유 전자쌍을 시각화하지만 학생용 표시/숨기기 제어는 없다.
  - 실제 3D의 초기 방향과 화면 맞추기 제어는 고급/교사 화면에 한정된다.
  - 학생 활동 화면의 구조 비교 슬롯은 렌더링하지 않는다.

### 5.5 결과 정보 위계

- 현재 상태: 부분 구현
- 증거: E2
- 확인 사항:
  - 검증 전 분자식과 분자량을 확정값으로 표시하지 않는다.
  - 학생 기본 화면에서 raw SMILES, MOL, CID, 개발자 로그는 숨긴다.
  - 평균 분자량이 학생 기본 결과 카드에 계속 노출되어 메타프롬프트의
    `기타 정보` 우선순위와 다르다.

### 5.6 오류 피드백과 회복

- 현재 상태: 서비스·단위 테스트 수준 부분 구현
- 증거: E2
- 확인 사항:
  - 빈 구조, 잘못된 구조, 미지원 VSEPR, 제출 인증 부재, 제출 endpoint 실패의
    학생 메시지가 있다.
  - 제출 중복 클릭 방지 상태와 로컬 저장 후 원격 제출 순서가 있다.
  - 수업방 endpoint가 잘못된 수업코드나 입장코드를 거절해도 클라이언트
    서비스는 local fallback 성공으로 바꾸므로 잘못된 코드와 네트워크 장애의
    사용자 의미가 분리되지 않는다.
  - 학생 입장 오류와 구조 검증 오류의 `aria-live`, `aria-invalid`,
    입력-오류 연결이 부족하다.
  - Playwright 오류 시나리오는 없다.

### 5.7 모바일·접근성

- 현재 상태: 일반 1열 반응형만 부분 구현
- 증거: E3 시각 캡처, 핵심 상호작용 E0
- 확인 사항:
  - 820px 이하에서 주요 그리드를 한 열로 바꾼다.
  - 모바일 하단 5탭, `safe-area-inset-*`, 3D `touch-action`,
    스크롤 충돌 방지 규칙이 없다.
  - 390×844 full-page PNG의 실제 캔버스는 390×8,185px이며, 분자 선택부터
    제출·3D 측정·푸터까지 하나의 긴 세로 흐름으로 배치된다.
  - 768×1024 full-page PNG도 768×7,166px로, 태블릿에서 단계 전환 없이 모든
    기능이 세로로 이어진다.
  - 네 캡처에서 페이지 자체의 가로 잘림이나 겹침은 보이지 않지만, Ketcher
    전체 툴바가 작은 폭에 조밀하게 남아 있다.
  - 일반 주요/보조 버튼 CSS의 명시적 최소 높이는 38px이며, 현재 화면 전체의
    44×44px 계산 크기는 실행 검증되지 않았다.
  - `prefers-reduced-motion` 규칙은 있으나 과거 진행 레일과 로딩 스피너 중심이다.
  - 200% 확대, 키보드 순서, 모바일 가로 모드, 화면 키보드 가림은 미검증이다.

## 6. Playwright 범위

현재 `apps/workbench/e2e/molecule-workbench.spec.ts`의 세 시나리오는 다음과 같다.

| 시나리오 | 현재 확인 | 증거 | 부족한 부분 |
|---|---|---|---|
| 윤리 게이트와 역할 선택 | 성공 | E3 | 접근성 키보드 흐름 미검증 |
| 학생 H2O 정상 흐름 | 예제 로드, H2O/18.015, 두 뷰어 표시, 생각 작성, mock 제출 성공 | E3 | 중심 원자, 전자 영역, 비공유 전자쌍, 배열, 분자 구조, 3D 조작 미검증 |
| 교사 피드백 흐름 | mock 제출 조회, AI 초안, 교사 수정, 반환 성공 | E3 | 수업방 생성, 실제 인증, 실제 Firestore 회귀 미검증 |
| CH4·NH3·H2O 비교 | 없음 | E0 | 신규 시나리오 필요 |
| 필수 오류 처리 | 없음 | E0 | 입장·RDKit·VSEPR·3D·제출 실패 mock 필요 |
| 모바일 390×844 | 없음 | E0 | 모바일 프로젝트와 성공 스크린샷 필요 |

Playwright 설정은 Desktop Chrome 프로젝트 하나이며, 성공 스크린샷은 자동
보존하지 않는다. API와 Firebase 인증은 E2E 모드에서 mock/stub 경계를 사용한다.

개선 작업용으로 추가된 미커밋 `apps/workbench/e2e/ux-redesign.spec.ts`는 네
뷰포트에서 검증된 H2O 활동을 열고 full-page PNG를 저장하며 문서 폭과 viewport
폭의 차이가 1px 이하인지 확인하도록 작성되어 있다. 이 파일은 baseline PNG
생성 경로를 재현하는 보조 증거이지만, 아래 표의 이미지에는 개선 diff의
5단계 진행 UI가 보이지 않으므로 **개선 전 비교 이미지**로만 사용한다.

## 9. 추정과 확인의 경계

### 확인됨

- 설치, 타입 검사, 253개 단위 테스트, 빌드, 3개 E2E가 성공했다.
- 프로덕션 URL이 HTTP 200을 반환했다.
- baseline 기준 커밋에는 5단계 진행 컴포넌트와 간편 편집 모드가 없다.
- baseline Playwright 설정에는 모바일 프로젝트가 없다.
- 지정된 네 baseline PNG가 생성되었고 각 전체 페이지를 육안 확인했다.
- baseline PNG에는 개선 diff의 5단계 진행 UI, 간편 모드, 모바일 하단 탭이 없다.

### 추정 또는 미검증

- baseline PNG에서 가로 잘림은 보이지 않지만, 390px 문서 폭 계산과 각
  상호작용 상태의 가로 스크롤 여부는 캡처만으로 모두 증명되지 않는다.
- CSS `min-height: 38px`만으로 모든 버튼이 실제 44px 미만이라고 단정할 수 없다.
  계산된 터치 영역을 브라우저에서 측정해야 한다.
- 프로덕션 HTTP 200만으로 Firebase 입장, 제출, 교사 피드백이 정상이라고
  단정할 수 없다.
- 현재 시각 완성도 점수는 최신 스크린샷 부재로 보수적으로 산정했다.
