# 개인정보처리방침

`다양한 분자의 분자구조 모델링`(이하 "본 서비스")은 수업용 분자 구조
그리기·검증·3D 비교와 교사 피드백을 제공하는 학습지원 웹앱입니다.

이 문서는 2026-07-27 작업 트리의 실제 데이터 흐름을 설명하는 운영 초안입니다.
현재 변경분은 프로덕션 배포가 확인된 상태가 아닙니다. 학교에서 서버 제출 기능을
활성화하기 전에는 학교 개인정보 담당자 검토, 운영 주체·보유 기간·삭제 담당자,
사용하는 Firebase·AI 환경을 확정해 이 문서를 배포 환경에 맞게 다시 게시해야
합니다.

## 1. 웹사이트 게시 및 이용 안내

본 서비스는 화면 하단에 개인정보처리방침, 이용약관, 정보관리책임자와 저작권
표시를 제공합니다.

학생은 수업코드, 입장 확인코드와 수업용 닉네임으로 입장합니다. 실명, 학번,
전화번호, 이메일, 주소 등 수업에 불필요한 개인정보를 닉네임이나 자유서술
답변에 입력하지 않아야 합니다. 교사는 배포 전에 학생과 보호자에게 실제 저장
위치와 운영 기간을 안내해야 합니다.

## 제1조 처리 목적

본 서비스는 다음 목적으로 필요한 범위의 정보를 처리합니다.

1. 수업방 입장과 권한 확인
   - 수업코드와 입장 확인코드 검증
   - Firebase 익명 UID와 수업용 닉네임을 이용한 수업 멤버십 확인
2. 학생 학습 활동
   - 2D 분자 구조, RDKit.js 검증 결과, VSEPR 교육용 예측, 3D 관찰 제공
   - 학생의 예측·비교·정리 답변과 제출 상태 관리
3. 교사 피드백
   - 교사가 담당 수업의 제출만 조회하고 피드백 초안을 검토·반환
4. 선택적 로컬 기록
   - 이용자가 명시적으로 저장한 활동 결과의 미리보기·내보내기
5. 외부 구조 자료 확인
   - 검증된 구조 식별값으로 PubChem 후보와 3D SDF를 조회

## 제2조 처리 항목과 저장 위치

### 2.1 학생 세션과 수업 멤버십

- 처리 항목: 수업코드, 수업용 닉네임, 앱이 생성한 익명 학생 식별자,
  Firebase 익명 UID, 인증 상태, 활동 시작·입장 시각
- 입장 확인코드: trusted endpoint로 전송해 검증하지만 학생 제출 문서에는
  저장하지 않습니다. 수업방에는 원문이 아닌 salt가 적용된 해시를 저장합니다.
- 저장 위치: 현재 탭의 앱 상태, Firebase Auth, 구성된 경우 Firestore 수업
  멤버십 문서

### 2.2 학생 제출과 교사 피드백

- 처리 항목: 수업코드, Firebase UID, 수업용 닉네임, 익명 학생 식별자,
  활동명, 학생 답변, 분자 구조 snapshot과 검증 결과, 3D 관찰·비교 내용,
  제출·수정 시각, 제출 상태, 교사 피드백
- 저장 위치: trusted `/api/save-submission` 및 피드백 endpoint가 연결된
  Firestore 수업방의 제출 문서
- 브라우저 저장: 위 식별자와 제출 snapshot 전체를 `localStorage` 제출함에
  복사하지 않습니다. 전송 중·재시도용 입력은 현재 학생 세션 메모리에만
  유지합니다.

### 2.3 교사 인증

- 처리 항목: Firebase 교사 UID, 이메일, 표시 이름, 인증 제공자, 교사 권한
  custom claim과 로그인 시각
- 저장 위치: Firebase Auth 및 현재 앱 세션
- 긴급 로컬 교사 모드는 trusted 서버 제출 조회·수업방 생성·피드백 반환
  권한으로 사용하지 않습니다.

### 2.4 이용자가 선택한 브라우저 활동 결과

- 처리 항목: 학생이 명시적으로 저장한 활동 답변, 구조 확인 결과, 3D 관찰과
  내보내기용 활동 snapshot
- 저장 위치: 현재 브라우저의 `localStorage`
- 주의: 공유 기기에서는 다음 사용자가 브라우저 저장 자료를 볼 수 있으므로
  수업 종료 전에 앱의 저장 결과 삭제 또는 브라우저 사이트 데이터 삭제가
  필요합니다. 이 저장 기능은 교사 제출의 성공 영수증이 아닙니다.

### 2.5 외부 서비스 요청

- PubChem: 검증된 canonical SMILES 또는 선택한 CID와 같은 화학 구조
  식별값을 전송합니다. 학생 닉네임·답변을 보내지 않습니다.
- AI 피드백: 서버에 AI provider가 설정된 경우 교사 권한 확인 후 제출의
  최소 학습 요약을 서버에서 provider로 보낼 수 있습니다. 전송용 복제본과
  provider 응답의 이메일, 한국 유선·휴대·인터넷 전화번호와 국가번호 변형,
  주민·외국인등록번호형 문자열, `학번`·`학생번호` 식별자는
  `[개인정보 삭제]`로 치환하고 명시 profile field는 제외합니다. 비정상
  provider 응답 원문은 브라우저 오류 payload에 그대로 반환하지 않습니다.
  이 처리는 Firestore 원본을 자동 수정하지 않으며 이름 등 비정형 개인정보를
  완전히 탐지할 수 없으므로, 학생은 개인정보 입력을 피하고 교사는 원본과
  응답을 확인한 뒤에만 전달해야 합니다. 브라우저에 AI API key를 두지 않으며,
  교사 검토 전 결과를 학생에게 자동 전달하지 않습니다.
- 실제 운영자는 사용하는 Firebase 프로젝트, AI provider, 처리 위치와 계약
  조건을 배포용 방침에 구체적으로 기재해야 합니다.

## 제3조 보유 기간

1. 현재 탭 메모리의 미제출 답변과 파생 상태
   - 새 학생 세션 입장, 역할·학생 identity 변경 또는 앱 상태 초기화 때
     삭제합니다.
2. 브라우저에 명시적으로 저장한 활동 결과
   - 이용자가 앱에서 개별·전체 삭제하거나 브라우저 사이트 데이터를 지울
     때까지 보관됩니다.
3. Firestore 학생 멤버십·제출·피드백
   - 현재 코드에는 자동 TTL 또는 학생용 self-service 삭제 기능이 없습니다.
   - 운영 주체는 배포 전에 수업 종료일에 맞춘 보유 기간과 관리자 삭제 절차를
     확정해야 합니다. 이 절차가 없는 환경에서는 실제 학생 제출 수집을
     활성화하지 않습니다.
4. Firebase 인증 정보
   - Firebase Auth 설정과 로그아웃·계정 정리 정책에 따릅니다.

## 제4조 처리하지 않도록 설계한 항목

본 서비스의 기본 입력은 주민등록번호, 주소, 전화번호, 학생 이메일, 실명,
학번, 건강정보 등 민감하거나 수업에 불필요한 정보를 요구하지 않습니다.
자유서술 입력에 이러한 정보가 포함되지 않도록 교사가 사전에 안내해야 합니다.

## 제5조 아동·청소년 수업 운영

학교 수업에서 학생이 본 서비스를 사용할 경우 담당 교사는 학교의 개인정보
보호 지침과 필요한 안내·동의 절차를 먼저 확인해야 합니다. 특히 Firestore
제출 저장이나 외부 AI provider를 활성화할 때는 실제 처리 항목, 보유 기간,
삭제 요청 방법을 학생과 보호자에게 알린 뒤 운영해야 합니다.

## 제6조 삭제와 파기

1. 브라우저 활동 결과
   - 앱의 저장 결과 삭제 기능 또는 브라우저 사이트 데이터 삭제로 제거합니다.
2. 미제출 학생 답변
   - 새 학생 identity로 전환할 때 메모리 상태를 초기화하며, 개인정보가 포함된
     제출 snapshot을 origin-wide 제출 키에 영속 저장하지 않습니다.
3. Firestore 자료
   - 현재 학생 화면에는 서버 자료 삭제 버튼이 없습니다. 학생·보호자의
     열람·정정·삭제 요청은 담당 교사 또는 정보관리책임자에게 전달하고,
     Firebase 관리자 권한이 있는 운영자가 확인 후 처리해야 합니다.
4. 레거시 브라우저 제출 키
   - 이전 버전이 남긴 `molecule-workbench-activity-submissions` 키는 앱 시작
     시 정리합니다.

## 제7조 안전성 확보 원칙

- RDKit.js 검증을 통과하지 않은 구조와 모호한 query 구조는 계산·외부 3D
  결과에 사용하지 않습니다.
- 학생 제출은 Firebase ID token, 수업 멤버십과 서버 소유권 검사를 통과해야
  저장됩니다.
- 교사 제출 조회와 피드백 수정은 교사 custom claim 및 담당 수업 범위로
  제한합니다.
- 학생 A의 미제출 답변·완료 상태를 학생 B 세션으로 넘기지 않습니다.
- service account, private token과 AI API key는 브라우저 번들·공개 저장소에
  저장하지 않습니다.
- 배포 시 HTTPS와 Firestore Security Rules를 사용하고 emulator 회귀 테스트를
  통과한 규칙만 반영합니다.

## 제8조 정보주체의 요청

학생 및 보호자는 담당 교사 또는 아래 정보관리책임자를 통해 보관 자료의 확인,
정정·삭제와 처리 중지를 요청할 수 있습니다. 요청 시 운영자는 해당 수업코드와
Firebase UID 또는 앱의 익명 식별자를 이용해 대상 자료를 확인하되, 추가
개인정보를 불필요하게 수집하지 않아야 합니다.

## 제10조 변경

- 적용 예정일: 2026년 7월 27일
- 변경 사유: Firebase 수업 멤버십·제출·피드백 흐름과 외부 자료 조회를
  반영하고, 공유 브라우저의 학생 제출 `localStorage` 영속 저장을 제거했습니다.
- 프로덕션 배포 전 실제 운영 환경과 학교 절차에 맞춰 다시 검토·게시합니다.
